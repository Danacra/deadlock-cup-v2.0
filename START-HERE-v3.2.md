# Deadlock Cup v3.2 — установка и исправления

## Что изменилось

- Восстановлена первоначальная палитра **#0A0A0A / #B6FF00**.
- Удалены старые коллажи, ненужная галерея и краткое досье героев.
- Добавлено отдельное окно `viewer.html` для настоящих 3D-моделей героев.
- Подготовлена поддержка `.glb` и `.gltf` через `models.json`; модель можно загрузить локально из `.glb` для проверки.
- Исправлена схема проверки администратора в Edge Function `steam-avatar`: та же RPC-функция `is_admin`, что и на сайте, RLS по пользовательскому JWT.
- Сохранены команды, турнирная сетка, OBS и согласие на публикацию Steam-аватаров.

## Обновление работающего сайта на Render

1. **Не удаляйте существующую базу Supabase.** Сохраните данные и при возможности сделайте резервную копию.
2. Распакуйте ZIP и замените файлы в GitHub (или загрузите полную сборку в новый репозиторий).
3. **Не заменяйте ваш настроенный `config.js` на шаблон** из архива. В нём должны остаться URL и publishable key вашего Supabase.
4. Опубликуйте изменения на Render (при автодеплое достаточно Commit changes). Затем обновите страницу с очисткой кэша (`Ctrl+F5`).
5. **Обязательно обновите Steam Edge Function**: Supabase → Edge Functions → `steam-avatar` → Code → замените содержимое `index.ts` файлом из `supabase/functions/steam-avatar/index.ts`, затем Deploy.
6. Проверьте секрет `STEAM_WEB_API_KEY` в Supabase → Edge Functions → Secrets. Не добавляйте его в GitHub.
7. Войдите в админ-панель снова, проверьте `↻ STEAM ФОТО` у одобренного участника с согласием на публикацию.

Новая SQL-миграция **не требуется**, если ваша база уже работает с v3.1.
Не запускайте `schema.sql` или `upgrade-tournament.sql` повторно на работающей базе.
Если сетка ранее выдавала `DELETE requires a WHERE clause`, установите **только** `supabase/fix-bracket-v2.8.sql`, предварительно проверив, что эта правка ещё не применена.

## Подключение 3D моделей

`viewer.html` — отдельная вкладка. В регистрации выберите героя и нажмите «ОТКРЫТЬ ГЕРОЯ В 3D».

Архив **не содержит игровые 3D-модели**. В `models.json` пока пустой объект `{}`.
Модели нужно добавить отдельно из источника, который разрешает использование и публикацию. Лучше разместить файлы `.glb` в папке `models`, затем добавить сопоставление:

```json
{
  "Abrams": "./models/Abrams.glb",
  "Yamato": "./models/Yamato.glb"
}
```

Это примеры путей, а не включённые файлы. Если у вас уже есть сайт с моделями, пришлите его адрес — тогда можно проверить формат, доступность модели и условия использования. Сайт с просмотрщиком без прямых `.glb`/`.gltf`-ссылок нельзя автоматически подключить как модель.

Вы также можете открыть `viewer.html` и выбрать локальный `.glb`: он отобразится только на вашем устройстве и не сохранится на сервере.

3D-просмотрщик загружается по необходимости с Google `<model-viewer>` CDN; для удалённых моделей необходимы корректные CORS-права.

## Проверки и ограничения

- Регистрация и команды не зависят от загрузки 3D-моделей.
- Доступ к личным анкетам ограничен прежними RLS-политиками Supabase.
- Если Steam отвечает 403 после обновления, сверьте, что вы вошли в Supabase Auth той же учётной записью, которой выдана роль в `app_admins`.
- Проверена структура HTML, синтаксис JavaScript и упаковка архивов. Реальная работа с вашей базой Supabase и внешними 3D-файлами требует проверки после публикации.

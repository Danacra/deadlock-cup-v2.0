# Deadlock Cup 3.1 — The Cursed City

## Новое в 3.1

- Полная новая цветовая система: тёмно-синий, кремовый, кирпично-красный, латунное золото.
- Галерея игровых персонажей и дополнительные изображения в шапках всех публичных разделов.
- Досье получает данные **по одному герою**, без скачивания всего общего каталога.
- Источники игровых данных: Deadlock API (`api.deadlock-api.com`) и резервно Deadlock Data API (`deadlock-data-api.iainfox.dev`).
- Встроенное краткое описание героя доступно **без API**. Точные данные о навыках зависят от доступности внешних источников.
- Весь сайт и OBS оформлены в одной палитре.
- Сохранены регистрация, команды, сетка, админка, OBS, Steam-функция.

## Вариант A — обновление существующего работающего сайта (рекомендую)

1. **Не удаляйте Supabase** — там хранятся ваши регистрации, команды и матчи.
2. Скачайте архив и распакуйте `deadlock-cup-site`.
3. Сохраните ваш текущий `config.js` из GitHub или из локальной копии. Файл из нового архива содержит только плейсхолдеры.
4. В GitHub загрузите все файлы из `deadlock-cup-site`, замените старые, а потом **верните ваш настроенный `config.js`**.
5. Сохраните изменения (Commit). Render → Static Site автоматически развернёт новую сборку.
6. На опубликованном сайте выполните `Ctrl+Shift+R` (жёсткое обновление) или откройте его в приватной вкладке.
7. Откройте вкладки Регистрация → Участники → Команды → Сетка → Организатор и убедитесь, что ваши данные сохранились.

**SQL-файлы при обновлении дизайна выполнять не нужно.** Если ранее сетка возвращала ошибку `DELETE requires a WHERE clause`, отдельно выполните только `supabase/fix-bracket-v2.8.sql` один раз. Не запускайте `schema.sql` или `upgrade-tournament.sql` повторно по действующей базе — версия функции может конфликтовать с уже созданной.

## Вариант B — совершенно новый сайт с нуля

1. Создайте Supabase-проект и выполните `supabase/schema.sql`, затем `supabase/upgrade-tournament.sql` и `supabase/upgrade-visuals.sql` **на новой пустой базе**. При изменениях версии функций может понадобиться ручная адаптация; на существующей базе используйте вариант A.
2. Создайте администратора в Authentication → Users, затем назначьте роль в таблице `app_admins` через SQL.
3. Запишите только **Project URL** и **Publishable key** в `config.js`. Никогда не вставляйте database password или secret/service_role key в сайт.
4. Создайте GitHub-репозиторий и загрузите файлы прямо в корень (рядом должны лежать `index.html`, `app.js`, `styles.css`, `config.js`).
5. На Render создайте **Static Site** с параметрами: Branch `main`, Root Directory пустой, Build Command `echo ready`, Publish Directory `.`.
6. Проверьте отправку тестовой заявки, приватность полей и возможность зайти в админ-панель.

## Доступность игровых изображений

Портреты грузятся с публичных серверов игровых ресурсов. Если часть адресов недоступна, вместо сломанной картинки показывается заглушка. Нельзя гарантировать, что изображения будут доступны круглосуточно, если серверы сообщества временно не работают. В таком случае регистрация и всё управление турниром продолжают работать.

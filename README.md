# DEADLOCK CUP — чистая сборка v3.0

Полный готовый **статический** сайт турнира Deadlock: регистрация, приватная админка, публичные ники, команды по 6 игроков, сетка, ссылки для OBS и опциональные Steam-аватары.

## Важно перед началом

**Не удаляй старый проект Supabase.** В нём хранятся твои реальные регистрации, составы команд и матчи. Файлы HTML/CSS/JS можно заменить безопасно, но база данных — отдельно.

- Портреты загружаются с сообщества Deadlock API и резервных общедоступных хостингов. Если картинка недоступна, появляется оформленная заглушка с буквами: сломанной иконки быть не должно.
- Подробные игровые сведения загружаются **только по кнопке** «Загрузить описание». При недоступности API открывай «Справочник»; каталог и регистрация продолжают работать.
- **Нет встроенной приватной серверной базы**: её предоставляет Supabase, с RLS-политиками. Demo mode в браузере — только для предварительного знакомства, он не сохраняет данные для всех пользователей.
- Steam-аватары требуют специальной Edge Function и добровольного согласия игрока. Без настройки Steam основная регистрация и сетка должны работать.
- Файл шрифта ValveOccult-SemiBold.ttf не включён. Если у тебя есть право использовать и публиковать его, можешь добавить его сам рядом со `stable-v3.css`.

## Путь A — восстановить сайт и сохранить существующих игроков (рекомендуется)

### 1. Резервная копия

1. В Supabase → Table Editor убедись, что таблицы `registrations`, `tournament_teams`, `team_members` по-прежнему содержат данные.
2. При необходимости экспортируй их через Supabase или через экспорт в старой админке. **Не запускай `schema.sql` над существующим проектом и не удаляй таблицы.**
3. Сохрани из старого репозитория свой `config.js` или найди параметры подключения в Supabase → Connect.

### 2. Подключить текущую базу

Открой `config.js`, замени:

```
export const SUPABASE_URL = 'https://ТВОЙ-ПРОЕКТ.supabase.co';
export const SUPABASE_PUBLISHABLE_KEY = 'sb_publishable_...';
```

Вставь реальный Project URL и Publishable key из Supabase → Connect (или Settings → API Keys). **Никогда не вставляй секретный ключ, пароль базы или пароль администратора в `config.js`.**

Если ранее использовался `anon` key, допускается и он для совместимости, при корректных RLS.

### 3. Починить сетку (если раньше было `DELETE requires a WHERE clause`)

В Supabase → SQL Editor → New query запусти **только** содержимое `supabase/fix-bracket-v2.8.sql`. Этот файл переопределяет две функции. Не удаляет команды и текущие матчи при самом применении, но кнопка «Сформировать сетку» позже **пересоздаст матчи**, если ты её нажмёшь.

Если Steam-аватары и цвет/эмблема команд уже работали, `upgrade-visuals.sql` повторно запускать не требуется. Если отсутствуют соответствующие поля — выполни один раз `supabase/upgrade-visuals.sql` (после резервной копии).

### 4. Создать новый репозиторий GitHub без старых файлов

1. Создай новый репозиторий, например `deadlock-cup-clean`.
2. Загрузи **содержимое** папки `deadlock-cup-site/` из архива. Корень GitHub должен содержать `index.html` и `config.js`, а не дополнительную вложенную папку.
3. Commit changes. Проверь, что `config.js` не содержит секретных ключей.

### 5. Запустить на Render

1. Render Dashboard → New → Static Site.
2. Подключи новый GitHub-репозиторий.
3. Branch: `main`; Root Directory: пусто; Build Command: `echo "Static site"`; Publish Directory: `.`.
4. Создай сайт. Render выдаст адрес вида `https://...onrender.com`.
5. Открой адрес. При подключении к прежнему Supabase появятся прежние участники и команды.
6. Логи админки: `https://...onrender.com/#admin` — используй **тот же** email/пароль администратора Supabase.

Вместо нового Render-сайта можно заменить файлы **в старом репозитории**, но обязательно удалить оставшиеся старые `visuals.*`, `animations.*`, `layout-v28.css` и `urn3d.js`, иначе их можно случайно снова подключить при дальнейших обновлениях.

## Путь B — совершенно новый Supabase (начать с нуля)

**Этот путь не переносит старых игроков**. Лучше использовать путь A.

1. Supabase → New Project → создай проект.
2. SQL Editor: последовательно выполни `supabase/schema.sql`, `supabase/upgrade-visuals.sql`, `supabase/fix-bracket-v2.8.sql`. Запускай в указанном порядке, **только в новом пустом проекте**.
3. Authentication → Users → Add user → Create new user, указав собственный email и пароль. Скопируй его UID.
4. SQL Editor, замени `СВОЙ-UID`:

```sql
insert into public.app_admins (user_id)
values ('СВОЙ-UID'::uuid)
on conflict (user_id) do nothing;
```

5. Скопируй Project URL и Publishable key в `config.js`. После этого повтори GitHub + Render из пути A.

## Проверка после публикации

- [ ] Участники отображаются и публично видны **только ники** (и аватары при согласии).
- [ ] Регистрация позволяет выбрать от 1 до 3 героев. Список не сбрасывает прокрутку и не меняет досье при движении мыши.
- [ ] Досье не мешает регистрации; при ошибке внешнего API нет бесконечной загрузки.
- [ ] Вход в админку работает; контакты не видны посторонним.
- [ ] Две команды создаются, принятые игроки переносятся между командами.
- [ ] Кнопка «Сформировать сетку» при 2 командах создаёт финальный матч.
- [ ] В OBS Browser Source работают адреса `overlay.html?mode=match`, `overlay.html?mode=roster`, `overlay.html?mode=teams`.

## Если что-то не работает

- «Деморежим» = в `config.js` ещё шаблон или некорректные параметры подключения.
- Ошибка `get_public_avatar_roster` = попробуем базовую публичную таблицу `public_roster` автоматически; для аватаров нужен `upgrade-visuals.sql`.
- «Проблема с Steam» = необязательная функция, смотри Supabase → Edge Functions → steam-avatar → Logs. Не надо переписывать сайт или удалять заявки.
- «DELETE requires a WHERE clause» = выполни `fix-bracket-v2.8.sql` и затем повтори создание сетки.
- «Невозможно загрузить портрет» = внешний URL недоступен; сайт покажет заглушку. API и источники портретов могут меняться при обновлениях Deadlock.
- Отсутствует играющий шрифт = добавь самостоятельно `ValveOccult-SemiBold.ttf` (по лицензии) или используй штатный fallback.

## Безопасность

В браузере используется **только Publishable key**. Для приватных анкет таблица `registrations` должна иметь RLS, запреты публичного SELECT и доступ только у админа. Публичный список ников отделён от личных данных. Не отправляй кому-либо service-role / secret key, Steam API Key и пароли.

## Файлы

- `index.html`, `styles.css`, `stable-v3.css` — сайт и новый стабильный дизайн.
- `app.js` — регистрация, список ников, админ-панель.
- `db.js` — связь с Supabase, каталог героев и локальный demo.
- `tournament.js` — команды и турнирная сетка.
- `overlay.html`, `overlay.css`, `overlay.js` — OBS.
- `config.js` — настройки проекта (в архиве только шаблон).
- `supabase/` — инструкции и SQL/Edge Function для нового или старого проекта.

Неофициальный фанатский сайт турнира; не связан с Valve.
